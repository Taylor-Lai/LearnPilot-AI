# ML 设计

## 目标

ML Service 将测评、学习行为、课程资源和知识图谱组合成“诊断—画像—推荐—规划—生成—辅导—反馈”的闭环。所有输出都应可解释、可离线复现，并在大模型不可用时保持核心学习能力。

## 输入

| 数据 | 主要字段 | 用途 |
| --- | --- | --- |
| 测评题目 | 知识点、难度、区分度、满分、预期用时 | 估计题目证据权重 |
| 作答结果 | 得分、用时、提示、尝试次数、自信度 | 估计掌握度与置信度 |
| 行为事件 | 资源、完成、得分、停留、点赞、时间、学习形式 | 更新画像和排序反馈特征 |
| 历史画像 | 上一轮掌握度 | 跨会话延续状态 |
| 课程资源 | 知识点、难度、形式、时长、质量、正文 | 推荐候选和 RAG 证据 |
| 知识图谱 | 知识点、先修关系、重要性 | 路径规划和图距离特征 |

## 诊断与画像

`DiagnosticEngine` 使用 Beta 先验融合历史掌握度，并根据题目难度、区分度、答题质量、时间适配、提示、尝试次数和自信度计算证据权重。输出包括掌握度、置信度、薄弱点、能力估计和未作答题目。

`StudentProfiler` 对行为按时间衰减，更新知识点状态，同时估计：

- 学习速度与建议学习节奏
- 投入度和稳定性
- 遗忘风险
- 认知形式偏好及其置信度
- 当前学习阶段和目标难度

## 推荐排序

排序特征版本为 `learning-ranker-v2`，包含：

- 薄弱度与掌握置信度
- 资源难度、时长和学习形式适配
- 资源质量与知识图谱距离
- 历史正负反馈和新颖度
- 学生投入度与遗忘风险

训练数据按学生分组划分训练集和验证集。构造某次目标交互的特征时，只使用该交互之前的历史，避免标签泄漏。模型工件记录训练时间、特征版本、训练/验证指标和数据指纹。

LightGBM 不可用或模型工件不兼容时，系统回退到可解释的加权基线；回退原因会出现在 `model_meta`。

## 学习路径

`LearningPathPlanner` 按掌握缺口、知识点重要性和先修关系排序，递归补齐未掌握的前置知识。每个步骤包含目标掌握度、推荐资源、预计时长、先修知识和阶段检查点。

## RAG 与生成

`ResourceRetriever` 对课程资源切片，融合 BM25 和 TF-IDF 相似度进行召回，并过滤零相关证据。

生成器要求学习卡包含：

- 知识点讲解和例子
- 个性化练习与参考答案
- 错因分析和复习建议
- 难度选择理由
- 实际召回切片的引用

质量检查会验证知识点覆盖、练习、答案、复习、错因、难度、安全性和引用白名单。任何未被召回的引用都会被移除。

## 智能辅导

辅导输入学生画像、问题、目标知识点、最近对话和课程证据。输出分层提示、追问、下一步行动和知识检查，优先引导学生推理而不是直接给出结论。

Qwen 调用失败或未配置密钥时使用确定性模板，保证离线测试与演示可用。

## 多智能体轨迹

完整学习闭环输出五类 `agent_traces`：诊断、画像、推荐、规划、生成与评估。辅导作为独立 Agent 通过 `/tutor/ask` 提供多轮交互。

## 评估

`learnpilot-ml-evaluate` 使用 `data/benchmarks/evaluation-cases.json` 计算：

- Recall@K、NDCG@K、MAP@K、MRR@K
- 推荐覆盖度、形式多样性和难度跨度
- 路径先修合理性
- 生成质量、证据引用率和可解释率
- 反馈后的掌握度提升示例

评估报告写入 `ml/reports/`，该目录可随时重建，不进入版本控制。
